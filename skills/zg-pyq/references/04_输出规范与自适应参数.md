# 04 · 输出规范与自适应参数（v2.0 精简版）

> 展开说明。**规则以 `../专家提示词.md` 为准**。
> 目标：同事**整段复制粘贴就能发**，不需要二次编辑。
> v2.0 变更：输出砍到 3 个小节；去掉过程字段与【需人工确认】；放开 emoji / 话题标签 / 承诺 / 限量。

## 一、固定输出结构（只有三个小节）

```
【文案 1】
<正文，已排好版，带分段与 emoji，可直接复制>

【文案 2】
<正文>

【文案 3】
<正文>

【本次判定】
素材类型：视频
视角档位：招生方
防折叠：已优化

【合规自检】
涉密与隐私红线：检测通过
合规红线：通过
```

## 二、每个字段写到什么程度

| 小节 | 写什么 | 明确**不要**写 |
|---|---|---|
| 【文案 N】 | 只有正文。上一条与下一条之间空一行 | 角度标签、字数、"适用：…"、场景说明、"以上" |
| 素材类型 | **只写类型名**：视频 / 单图 / 多图 / 聊天截图 / 金额截图 / 政策文件 / 岗位清单 / 纯文字需求 | 视频多长、图片清不清楚、能不能用、细节描述 |
| 视角档位 | 招生方 / 官方通告 | 判断依据 |
| 防折叠 | 已优化 / 未优化 | 做了哪几项、为什么不做 |
| 涉密与隐私红线 | 检测通过；命中并改写时补一句改法 | 大段解释 |
| 合规红线 | 通过 | 逐条列举 |

**已删除、不要再出现的字段**：产出类型、场景、发布对象、条数与字数、本次按默认、发布节奏、
防折叠合规边界、【需人工确认】小节。

## 三、正文写法硬要求

1. **第一行必须自足**：12–22 字，被折叠成一行也抓得住人。
2. **分段留白**：每段 1–2 行，段与段空一行；禁止整块糊在一起。
3. **emoji 当锚点**：每条 2–6 个，放行首；不堆叠三连。
4. **数字用阿拉伯数字**，比形容词可信。
5. **结尾一行行动 + 一处紧迫 + 一个 emoji**。
6. **不用 markdown 符号**（`#` 作标题、`*`、`>`、`-`）；`#话题` 只出现在末行。
7. **不复述素材**：不出现"视频中/图中/本次/该"这类旁白词。

## 四、自适应决策表

| 素材 / 需求 | 条数 | 每条字数 |
|---|---|---|
| 报到 / 入住 / 开班 / 集合现场 | 3 | 100–180 |
| 实训 / 上课 / 车间操作 | 3 | 100–180 |
| 企业 / 签约 / 入职 / 工牌 / 合影 | 2–3 | 100–180 |
| 政策 / 新闻 / 行业数据 | 2–3 | 120–200 |
| 岗位清单 / 招录条件（M3） | 1–2 | 200–320 |
| 师资 / 荣誉 / 成果 | 2 | 120–200 |
| 节点（退伍季 / 开学季 / 节日） | 2–3 | 80–140 |
| 纯文字需求 / 认知观点 | 3 | 100–180 |
| 学员反馈 / 聊天截图 | 2 | 80–140 |
| 金额截图（报名进度） | 2 | 60–120 |

【条数】显式填写时优先。三条候选的推荐组合：**现场感 / 观点或算账 / 名额紧迫**。

## 五、参数

| 参数 | 默认 | 取值 | 说明 |
|---|---|---|---|
| `MARKETING` | on | on / off | 承诺、限量、晒单、emoji、话题标签总开关；off 时全部关闭 |
| `EMOJI` | on | on / off | 每条 2–6 个 |
| `HASHTAG` | on | on / off | 末尾 2–4 个 |
| `URGENCY` | on | on / soft / off | 每条一处紧迫 / 只暗示 / 不提 |
| `VOICE` | 招生方 | 招生方 / 官方通告 | 官方通告＝去人称条目化，用于 M3 长通告 |
| `OUTPUT_TYPE` | auto | M1–M6 / auto | 素材不明显时走 M5 或 M1 |
| `TONE` | 热 | 热 / 稳 / 硬 | 有情绪有招呼 / 克制 / 强催单 |
| `CANDIDATES` | auto | auto / 整数 | 条数 |
| `LENGTH` | auto | auto / 区间 | 字数 |
| `ANTI_FOLD` | auto | auto / on / off | 输出只写结果 |
| `SHOW_AMOUNT` | false | true / false | 金额截图是否写具体数字 |
| `DISCLAIMER` | none | none / auto | auto＝政策类结尾带一句"具体以官方公告为准" |
| `HARD_REDLINE` | 涉密与他人隐私 | 常量 | 不可关闭 |

单次覆盖写法：`【条数】3 条`、`【类型】M1`、`【视角】官方通告`、`【补充】30 个名额，剩 6 个`。

## 六、合规自检写法

- 通过：`涉密与隐私红线：检测通过` / `合规红线：通过`。**后面不跟解释、不跟括号。**
- 命中改写：`涉密与隐私红线：命中并已改写（画面铭牌未复述）`。
- 需要提醒发布前处理的事（如截图手机号），用一句话接在合规自检下面，**不加小节标题**：
  `注：截图内有手机号，发布前请打码。`

## 七、出稿前最后一眼

[ ] 三条是不是都落到了"人"和"选择"上，而不是介绍素材？
[ ] 第一行能不能独立抓人？
[ ] 有没有具体到方向、时长、去向、待遇、年龄？
[ ] 每条只有一个紧迫点，没有三连催？
[ ] 排版有没有留白、emoji 有没有过量、有没有 markdown 符号残留？
[ ] 判定三行、自检两行，齐不齐？有没有多余的字段混进来？
