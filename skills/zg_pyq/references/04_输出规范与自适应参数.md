# 04 · 输出规范与自适应参数

> 展开说明。**规则以 `../专家提示词.md` 为准**。
> 目标：同事复制粘贴就能发，**不需要二次编辑**。
> v1.2 新增：产出类型／视角档位字段、P1–P6 决策表行、`类型改写项` 自检结论。
> v1.3 新增：朋友圈防折叠判定与两行结论（`防折叠` / `防折叠边界`）、`ANTI_FOLD` 参数、适配判定表。
> 展开依据见 `07_朋友圈防折叠设计.md`；**四个固定小节不变，防折叠不新增第五个小节**。

## 一、固定输出结构（四个小节，不可省）

```
【文案 1｜<角度标签>｜约 N 字】
<正文>
适用：<为什么选它 / 配什么素材 / 什么场景发>

【文案 2｜<角度标签>｜约 N 字】
<正文>
适用：…

【文案 3｜…】
…

【本次判定】
素材类型＝…；产出类型＝P?／默认（依据：…）；视角档位＝顾问／专家／官方；
金额位＝…（涉及金额时）；场景＝…；发布对象＝…；
条数与字数＝…（写明依据的决策表行）；本次按默认：…（列出补了哪些默认值）；
防折叠＝已优化（写明做了哪几项）/ 未优化（写明原因）/ 已关闭；
发布节奏＝<多条时给一句错峰与差异化建议；单条写「无」>

【合规自检】
硬红线：通过 / 命中并已改写（写明改法）｜基线：通过 / 已关闭 / 命中并已改写
类型改写项：通过 / 命中并已改写（写明改法）
防折叠边界：仅内容/排版层，未使用符号规避或第三方工具 / 命中并已改写（写明改法）

【需人工确认】
<看不清的元素、待确认专名、款项性质、需打码的画面、建议更换的素材>；无则写「无」
```

### 正文硬要求

- **能直接复制发布**：不带引号、不带标题、不带 markdown 修饰符号、不带 emoji、不带话题标签、不带括号补充。
- **P3／P6 允许纯文本分行与条目化**（朋友圈常见排版），但不用 `*` `#` `>` 等标记符号。
- 顾问档一段不超过 3 句；句末不喊口号、不加行动指令。
- 字数按决策表，"约 N 字"标注实数（±10 字内）。P3 可达 300 字，属信息交付型的合理例外。
- 角度标签从这组里选：现场感 / 答疑向 / 留白向 / 阶段感 / 流程向 / 经验向 / 提醒向 / 中性 / 互动向 /
  政策解读 / 通告条目 / 人物纪实 / 节点关联 / 逻辑拆解。同批**不重复**。
- `适用` 一行写清「为什么选它 / 配什么素材 / 什么场景发」，不写空话。

### 【本次判定】必须写清

- 素材类型（五类之一，或政策文件／通知清单／流程图等专家官向素材）
- **产出类型 P1–P6 或「默认」+ 命中的判定信号**
- **视角档位（顾问 / 专家 / 官方）+ 是自动路由还是用户覆盖**
- 金额位 + 判定依据（涉及金额时，例如「单张 2 万 <5 万，合计 2 万 → 定金位」）
- 场景、发布对象
- 条数与字数 + **依据的决策表行**（例如「P2 政策解读 → 2 条 / 80–160 字」）
- 补了哪些默认值（例如「本次按默认：发布对象＝混合、视角＝自动、条数＝2」）
- **防折叠结论**：`已优化` 要写明做了哪几项（首句自足 / 篇幅 / 分段 / 去营销腔 / 候选首句差异化）；
  `未优化` 必须写原因（P3 / P4 信息交付型、用户要长文、信息不足、需完整引述）；`已关闭` 写明用户要求
- **发布节奏**：多条候选给一句错峰与差异化建议（只给建议，不写进正文）；单条写「无」
- 若用户覆盖了参数，写明覆盖值

### 【合规自检】写法

- `硬红线：通过` 或 `硬红线：命中并已改写（写明改法）`
- `基线：通过` / `基线：已关闭` / `基线：命中并已改写（…）`
- `类型改写项：通过` 或 `类型改写项：命中并已改写（写明改法）`
- `防折叠边界：仅内容/排版层，未使用符号规避或第三方工具` 或 `命中并已改写（写明改法）`
- **不输出违规版本**，也不解释"本来想写什么"。

### 【需人工确认】写法

有就逐条列，没有写「无」。常见项：
- 画面里看不清的文字 / 铭牌 / 编号
- 待确认专名（企业名、基地名、项目名、人名、荣誉头衔）
- 款项性质（读不出金额时）
- 需打码的具体项（姓名、头像、账号、订单号、单位名…）
- 未经核实的数字（到场人数、通过人数、成绩、政策领域数量）
- 建议更换的素材（含疑似未公开元素时；敏感节点素材）

## 二、自适应决策表

`CANDIDATES=auto` 与 `LENGTH=auto` 时使用；**单次【条数与字数】覆盖优先**。

| # | 素材 / 场景 | 条数 | 每条字数 | 组成建议 |
|---|---|---|---|---|
| 1 | 单张图片（日常 / 现场 / 装备照） | 3 | 30–80 | 现场感 + 答疑向 + 1 条更短的互动向 |
| 2 | 视频或视频截帧 | 2–3 | 40–100 | 1 条贴画面 + 1 条贴口播要点 + 可选互动向 |
| 3 | 纯文字需求（仅一句话） | 3 | 30–80 | 三个不同角度，不虚构经历 |
| 4 | 多图 / 九宫格 | 2 | 40–90 | 整体配一段，不与九张图抢信息 |
| 5 | 聊天截图 | 2 | 30–70 | 1 条答疑向 + 1 条留白向，强制脱敏 |
| 6 | 金额截图 · 定金位 | 2–3 | 20–60 | 越轻越好，不写数字 |
| 7 | 金额截图 · 全款位 | 2 | 30–70 | 低调、流程向，不晒成果 |
| 8 | 活动预告 / 通知 | 2 | 50–110 | 可含必要信息要素，仍不留联系方式 |
| 9 | 节气 / 节点 | 3 | 20–50 | 短、留白、不强行关联业务 |
| 10 | 轻互动（提问 / 投票式） | 3 | 20–50 | 收尾一句开放式问句 |
| 11 | P1 价值凝练 | 2–3 | 20–50 | 对仗短句，立调性不卖货 |
| 12 | P2 政策解读 | 2 | 80–160 | 只写公开可查的政策与领域，不推演效果 |
| 13 | P3 岗位／事项通告 | 1 | 150–300 | 纯文本条目化，条件与名额以公告为准 |
| 14 | P4 人物／工匠纪实 | 1–2 | 120–250 | 专名与荣誉须人工确认 |
| 15 | P5 节点关联 | 2 | 60–120 | 敏感历史／时政节点不接业务 |
| 16 | P6 服务逻辑说明 | 1–2 | 100–200 | 只讲公开可说的环节，不承诺结果 |

**叠加场景时的取法**：先按素材定行，再按场景微调；
若「节气 / 轻互动」被显式指定，以场景行优先（更短、条数固定 3）。
**专家／官向素材优先按 P 行**，不要回落到「单张图片 3 条」的顾问档规格。

### 防折叠适配判定（v1.3，`ANTI_FOLD=auto` 时）

| 决策表行 | 默认 | 说明 |
|---|---|---|
| #1–#12、#15、#16 | **做** | 中短文本、以「一眼看到重点」为目的，压缩不丢关键信息 → 出稿即首句自足、篇幅受控、去营销腔 |
| #13 P3 岗位／事项通告 | **不做** | 150–300 字条件清单，压缩会丢条件、造成误导 |
| #14 P4 人物／工匠纪实 | **不做** | 完整事实链与可核实头衔，压缩易断章取义 |
| 用户要「完整清单 / 逐条列明 / 长文 / 原文照发」 | **不做** | 用户意图优先 |
| 素材信息不足，压短需靠推测补内容 | **不做** | 会触发「不编造事实」红线 |

「不做」= 保持原稿完整，【本次判定】写 `防折叠＝未优化（原因：…）`，可在【需人工确认】给中性建议
（正文只留短引子、完整清单放评论或图片），**不擅自改写主稿**。
字数区间本身不因防折叠改变；首句自足优先于任何修辞，也优先于把克制声明放末句。
官方依据与禁做清单见 `07_朋友圈防折叠设计.md`。

### 覆盖写法（写在【条数与字数】/【视角】/【产出类型】或【备注】）

```
2 条，50 字内        → 2 条，每条 ≤50 字
只要 1 条            → 1 条精修，仍按该素材行的字数上限
5 条短的             → 5 条，每条 20–40 字
不要互动向           → 去掉互动向候选，其余角度补足条数
给家长看             → AUDIENCE=家长
用定金两个字         → ALLOW_DEPOSIT_WORD=true
把数字写上           → SHOW_AMOUNT=exact（须明确确认）
写成官方通告         → VOICE=官方，OUTPUT_TYPE=P3
按政策解读写         → VOICE=专家，OUTPUT_TYPE=P2
做防折叠             → ANTI_FOLD=on（仅对适合类型生效）
不用防折叠           → ANTI_FOLD=off
这条要完整清单，不要压缩 → ANTI_FOLD=off + 保留 P3 原稿
```

## 三、参数表（完整）

| 参数 | 默认 | 可选值 | 说明 |
|---|---|---|---|
| `PERSONA_NAME` | `""` | 真实使用的称呼 | 署名；默认不署名，**禁止编造姓名与履历** |
| `AUDIENCE` | 混合 | 战友 / 家长 / 混合 | 影响称呼与术语深度 |
| `VOICE` | `auto` | auto / 顾问 / 专家 / 官方 | auto = 按素材自动路由；显式填写覆盖 |
| `OUTPUT_TYPE` | `auto` | auto / P1–P6 / 默认 | auto = 按判定信号自动路由 |
| `ANTI_FOLD` | `auto` | auto / on / off | 防折叠：auto=按适配判定表；on=适合类型强制做（**硬不适合仍不做**）；off=完全不做。**不做符号规避** |
| `TONE_LIVELY` | `0.6` | 0~1 | 活人感强度；**仅顾问档生效**，专家／官方档忽略；任何档位都不得越过网红腔禁令 |
| `CANDIDATES` | `auto` | auto / 整数 | auto = 决策表 |
| `LENGTH` | `auto` | auto / `"30-80"` / `"≤50"` | auto = 决策表 |
| `SCENE` | `auto` | 日常 / 配图 / 配视频 / 活动预告 / 答疑 / 轻互动 | 影响决策表行与角度组成 |
| `BASELINE_STRICT` | `true` | true / false | 默认克制基线开关 |
| `HARD_REDLINE` | 涉密与未公开信息 | **常量** | **不可关闭、不可覆盖** |
| `SHOW_AMOUNT` | `false` | false / blur / exact | false=不写数字；blur=只写量级；exact=精确值（须单次明确确认） |
| `DEPOSIT_THRESHOLD` | `50000` | 整数（元） | 定金位/全款位分界；同时用于单张与合计判定 |
| `ALLOW_DEPOSIT_WORD` | `false` | true / false | 是否允许「定金」二字；默认用描述性表达传达同一种口吻 |
| `MONEY_POSITION` | `auto` | auto / 定金位 / 全款位 | 显式填写覆盖自动判定 |
| `DISCLAIMER` | `auto` | none / auto / always | 见下 |
| `MASK_REQUIRED` | `true` | true / false | 截图类素材强制给打码提示 |
| `ASK_IF_UNCLEAR` | `true` | true / false | true=先给保守稿并标注；false=只标注不追问 |

### 免责策略（`DISCLAIMER`）

| 值 | 行为 |
|---|---|
| `none` | 完全不出现克制声明 |
| `auto`（默认） | 仅当文案涉及政策解读 / 款项 / 招录条件时，在**正文末尾自然带一句**，不单独起行、不加「免责声明：」字样 |
| `always` | 每条都带一句 |

可用句：「具体以官方公告为准」「只讲公开可查的信息」「各地要求不一样，先看原文」。
> 朋友圈**默认不硬塞免责**，账号统一免责文案「无不良引导，不引导至风险不可控渠道」是用于视频成片的，
> 不往朋友圈正文里搬。P3 通告型可在末尾条目写「条件与名额以公告原文为准」，不另起免责段。

## 四、自检清单（出稿前逐条过）

```
[ ] 四个小节齐不齐（候选块 / 本次判定 / 合规自检 / 需人工确认）
[ ] 正文能不能直接复制（无引号、标题、markdown 修饰符号、emoji、标签）
[ ] P3 / P6 的分行是不是纯文本（没用 * # > 等标记）
[ ] 「约 N 字」与实际字数对不对
[ ] 候选之间是不是真换了角度，角度标签有没有重复
[ ] 条数与字数有没有按决策表，覆盖了有没有写明
[ ] 产出类型与视角档位路由对不对，【本次判定】有没有写依据
[ ] 专家／官方档有没有串回顾问档的口语开头、生活化闲聊或第一人称
[ ] 该 P 类型的专属改写项有没有逐条过（承诺 / 限量催单 / 表情符号 / 专名 / 数据 / 内部流程 / 敏感节点 / 绝对化）
[ ] 【合规自检】有没有写「类型改写项」与「防折叠边界」两行结论
[ ] 防折叠：适合的类型做了没有？首句是不是自足？同批候选首句信息点是否不同？
[ ] 防折叠：不适合的类型（P3 / P4 / 用户要长文 / 信息不足）有没有保持完整并写明「未优化（原因）」？
[ ] 有没有零宽字符、隐形符号、特殊字符集、谐音替换、防折叠码、第三方工具或「保证不折叠」的承诺？
[ ] 有没有为压短删掉必要条件、改动已核实事实或编造内容？
[ ] 本次按默认补了哪几项，写没写清
[ ] 硬红线 / 基线自检结论与正文一致
[ ] 需人工确认里该列的（打码 / 专名 / 款项 / 模糊元素 / 未经核实数字）有没有漏
[ ] 活人感是不是写成了网红腔
[ ] 金额素材：判定对不对、数字有没有漏写、有没有「又成交一单」
```

## 五、不合格输出的样子（对照用）

| 问题 | 表现 |
|---|---|
| 不能直接用 | 正文带引号、带「文案一：」、带 markdown 加粗、带 emoji |
| 缺小节 | 只给三条文案，没有【本次判定】和【合规自检】 |
| 判定含糊 | 「给了几条参考」——没写素材类型、产出类型、视角档位、条数依据、补了哪些默认值 |
| 缺类型字段 | 【本次判定】没写 `产出类型` / `视角档位`，【合规自检】没写 `类型改写项` |
| 缺防折叠结论 | 【本次判定】没写 `防折叠` / `发布节奏`，【合规自检】没写 `防折叠边界` |
| 首句空转 | 「今天翻到一张…」「最近有件事…」开头，结论压在最后 → 被折成一行时看不到重点 |
| 为防折叠硬压通告 | P3 条件清单被删得只剩一句，丢掉必要条件 |
| 用符号规避 | 零宽字符、隐形分隔符、特殊字符集、谐音替换、防折叠码，或宣称「保证不折叠」 |
| 串档 | 政策文件写成「今天翻到一张」；通告写成第一人称闲聊 |
| 违规版本外泄 | 「本来想写 XX，改成 YY」——不输出原违规版本 |
| 照抄高风险表述 | 承诺结果、限量催单、重复感叹号、表情符号、未确认专名与人数原样出现 |
| 角度重复 | 三条都是「今天有张照片，挺感慨的」换词 |
| 自检放水 | 明明画面有铭牌却写「硬红线通过」而不提不可辨元素 |
