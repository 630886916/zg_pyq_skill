# 03 · 素材解析规则

> 展开说明。**规则以 `../专家提示词.md` 为准**。
> 核心原则：**实际看图 / 看帧，只写能确认的元素；看不清就当不可辨，不猜、不补、不由文案反向造画面。**

## 一、五类素材 · 逐步解析

### 1. 单张图片

```
① 辨认类型：海报 / 通知 / 现场照 / 装备照 / 证书 / 生活照 / 风景 / 截图
② 列出可确认元素：几个主体、大致场景、动作、色调氛围（只列看得清的）
③ 列出不可辨元素：模糊文字、铭牌、编号、人脸、水印 → 一律标为「不可辨」
④ 查敏感元素：型号参数 / 内部编号 / 看板 / 工牌 / 单位名 / 内部文件 → 命中即走 02 号文件第 1.2 节
⑤ 定规格：单张图片 → 决策表「3 条 / 30–80 字」，含 1 条更短互动向
⑥ 起草：可写「几台设备」「几个穿工装的背影」「一张车间随手拍」；不写设备是什么型号、哪个单位
```

⚠️ 常见错：从一张车间照里"看出"了具体工序名称、单位名、培训项目名 → 命中硬红线。

### 2. 视频或视频截帧

```
① 看画面：主体、场景、动作、是否有字幕 / 包装文字
② 有口播要点（用户给了或画面字幕可读）→ 记要点，不补没听到的话
③ 有字幕 / 标题卡 → 可作为已公开信息使用，但仍不写专名与未确认信息
④ 查敏感元素（同 1④）
⑤ 定规格：2–3 条 / 40–100 字；1 条贴画面 + 1 条贴口播要点，可选 1 条互动向
⑥ 起草：贴着画面走，不替视频编台词、不写「视频里说了…」以外的信息
```

### 3. 纯文字需求（无素材）

```
① 抽主题与场景：招录季 / 节气 / 答疑 / 活动预告 / 日常 / 轻互动
② 定规格：3 条 / 30–80 字，三个不同角度
③ 起草：用常识性场景与公开可查的通用信息
④ 禁止虚构具体经历：不写「今天去了某基地」「刚见了一位客户」「上周三位战友…」
       不编单位名、政策名、数据、案例、公告日期与名额
⑤ 【本次判定】写明补了哪些默认值（场景 / 发布对象 / 条数字数）
```

> 这一类是**最容易踩"编造"基线**的输入。宁可写得虚一点（「又到公告陆续出来的时候」），
> 也不要为了"活人感"编一个不存在的今天。

### 4. 多图 / 九宫格 / 聊天截图

```
① 整体看：这组图在讲什么（活动 / 现场 / 日程 / 咨询对话），不逐图解说
② 聊天截图：只把「有人问了什么、我怎么答的」抽象成答疑向，不复述原话、不引用第三人发言
③ 脱敏：姓名 / 头像 / 昵称 / 微信号 / 手机号 / 订单号 / 单位名 / 群名 / 看板 → 一律不进文案
④ 定规格：多图 2 条 / 40–90 字；聊天截图 2 条 / 30–70 字（1 条答疑向 + 1 条留白向）
⑤ 起草 + 【需人工确认】必写「发布前请打码（列出具体项）」
⑥ 禁止：把截图写成「客户好评 / 成功案例 / 又帮一位战友上岸了」式结果背书
```

### 5. 成交金额截图（专项）

见下一节。**这是用户明确指定的业务判断，按规则执行，不要自行"更正"。**

## 二、金额判定流程

```
输入：1 张或多张金额截图
  │
  ├─ 【款项性质】显式填写了？ ── 是 ──→ 直接采用填写值（覆盖自动判定）
  │                            否
  │                            ↓
  ├─ 逐张读金额，算合计
  │   ├─ 读不出 / 模糊 / 信息不全 ──→ 定金位（最保守）+ 标注需人工确认
  │   └─ 读得出
  │        ↓
  ├─ 合计 ≥ 5 万？ ────── 是 ──→ 全款位
  │                   否
  │                   ↓
  ├─ 单张 < 5 万？ ────── 是 ──→ 定金位
  │                   否 ──→ 定金位（保守）+ 标注需人工确认
  │                            ↓
  └─ 出口：定金位 / 全款位
```

**关键口径（用户 2026-11-10 原话落字）**

- 单张低于 5 万的，**即便它可能是总共全款里分笔的一笔**，也按定金的位置与口吻理解。
- 多张图片**总金额超过 5 万**，就理解为全款。
- 目的：同一批素材可能有多样用法，按素材的实际呈现做判断，而不是要求用户每次先解释款项性质。

### 判定示例表

| 收到的截图 | 合计 | 判定 | 说明 |
|---|---|---|---|
| 1 张 20,000 | 20,000 | 定金位 | 单张 <5 万 |
| 1 张 30,000 | 30,000 | 定金位 | 单张 <5 万 |
| 3 张 20,000 / 30,000 / 20,000 | 70,000 | **全款位** | 合计 ≥5 万 |
| 2 张 20,000 / 20,000 | 40,000 | 定金位 | 合计仍 <5 万 |
| 1 张 60,000 | 60,000 | 定金位（保守）+ 需确认 | 单张 ≥5 万且非多张分笔，走最保守 |
| 2 张，一张金额模糊 | 无法算 | 定金位 + 需确认 | 读不出 |
| 1 张 20,000，【款项性质】填「全款位」 | — | **全款位** | 显式覆盖优先 |

### 两个位怎么写

| | 定金位 | 全款位 |
|---|---|---|
| 语感 | 阶段性、轻量、未完结 | 正式确定、往下走流程 |
| 可用表达 | 先把意向金交了／预付款／先定下来／往前走了一小步／剩下的流程慢慢走 | 几笔都办完了／手续告一段落／材料也齐了／接下来按流程走 |
| 条数·字数 | 2–3 条 / 20–60 字 | 2 条 / 30–70 字 |
| 禁止 | 「成交」「收款 X 元」「又成一单」「名额有限」「涨价在即」、客户身份、结果承诺、暗示必有尾款 | 同左，且**不晒成果、不制造热闹** |
| 数字 | 默认不写（`SHOW_AMOUNT=false`），也不写「几万块」这类量级 | 同左 |
| 「定金」二字 | 默认不用（`ALLOW_DEPOSIT_WORD=false`），用描述性表达传达同一种口吻；参数打开后可用 | 同左 |

## 三、信息不足处置（`ASK_IF_UNCLEAR=true`）

| 情况 | 处置 |
|---|---|
| 占位留空 | 按默认补齐，在【本次判定】写明补了什么 |
| 图片模糊 / 文字不可辨 | 出中性保守稿 + 【需人工确认】写明哪些元素看不清 |
| 专名未确认 | 不落字，写「需人工确认」占位 |
| 款项性质读不出 | 走定金位 + 标注需人工确认 |
| 素材疑似涉密 | 中性稿 + 明确建议打码或换图；极端的只说明不使用该素材 |
| 用户给的需求与素材明显冲突 | 以**素材可确认的内容**为准，在【本次判定】说明，不按需求编画面 |

**不做的两件事**：不为了出稿而追问一堆问题；不为了"看起来完整"而补出画面里没有的信息。
出保守稿 + 明确标注，比停在那里等回复更好用。

## 四、素材 → 规格速查

| 素材 | 条数 | 字数 | 必须附带 |
|---|---|---|---|
| 单图 | 3 | 30–80 | 不可辨元素说明（如有） |
| 视频/截帧 | 2–3 | 40–100 | 贴画面 / 贴口播的角度区分 |
| 纯文字 | 3 | 30–80 | 【本次判定】列出补的默认值 |
| 多图 | 2 | 40–90 | 整体视角，不逐图 |
| 聊天截图 | 2 | 30–70 | 脱敏打码提示 |
| 金额 · 定金位 | 2–3 | 20–60 | 金额位判定 + 脱敏提示 |
| 金额 · 全款位 | 2 | 30–70 | 合计判定 + 脱敏提示 |
