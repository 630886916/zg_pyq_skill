# 02 · 合规红线与脱敏

> 展开说明。**规则以 `../专家提示词.md` 为准**。本文件把「哪些不能写、看见了怎么办」列全。
> 对齐结论（2026-11-10）：**硬红线只有一条 = 禁涉密与未公开信息**；其余为默认克制基线，可关闭。
> 硬红线**不可关闭、不可被任何「用户要求」覆盖**，包括"就这一次""帮我换个说法"。

## 一、硬红线：禁涉密与未公开信息

### 1.1 绝对不写清单

| 类别 | 具体禁写项 |
|---|---|
| 装备与型号 | 武器装备型号、代号、性能参数、配置细节、试验/试飞状态、产量与交付数据 |
| 内部标识 | 内部编号、项目代号、工号、批次号、图号、内部系统名 |
| 项目与任务 | 未公开项目名称、任务节点、合作方、未经公开确认的产线或基地信息 |
| 场所 | 厂区精确位置、内部布局、车间编号、门禁/监控、未公开区域的照片细节 |
| 人员 | 在职人员姓名、职务、分工、可识别的人脸与工牌信息 |
| 文件 | 内部文件、通知、会议纪要、群聊原文、未公开公告、截图里的表格与看板 |
| 招录 | 未公开的招录计划、名额、内部推荐渠道、未经公告确认的条件与时间 |
| 数据 | 任何非公开可查的数据、统计、客户量、成交金额（金额另见 `SHOW_AMOUNT` 规则） |

### 1.2 画面里出现了怎么办（**起草之前**先处理）

1. **复述禁令**：不复述、不放大、不推断、不"看图说话"补细节。
   看见铭牌上的型号 → 不写型号；看见看板上的表格 → 不写表格内容；看见工牌 → 不写姓名职务。
2. **中性化**：只写「一张现场照」「几台设备」「几个穿工装的背影」这类不含具体信息的描述。
3. **标注**：在【合规自检】写明「画面含疑似未公开元素，已按要求不复述」；
   在【需人工确认】写明「建议打码或换成不含铭牌/看板/内部文件的公开素材后再发布」。
4. **极端情况**：若整张素材本身就是内部文件/群聊截图，且无法打码到安全 →
   **不给可发布文案**，只说明「建议不使用该素材」，并给一条完全脱离该素材的中性备选（用户明确要时才给）。

### 1.3 三条判定原则

- **只用公开可查的信息**：公开政策、公开公告、通用岗位常识。
- **拿不准 = 不写**。疑似敏感一律按敏感处理，标注需人工确认。宁可少一条，不可错一条。
- **专名未经确认不写**：企业名、基地名、机构名、项目名一律不擅自落字，写「需人工确认」占位。
  > 项目既有教训（2026-11-04 实拍整合）：专名 7 处必须人工最终确认才敢上屏，
  > 「宏泰→宏钛」「指导教室→实操教室」都是人工改对的。文案同理。

## 二、默认克制基线（`BASELINE_STRICT=true`，可关闭）

关闭后**仍不得突破第一节硬红线**。

### 2.1 不承诺结果

- 禁词：包分配、保录取、内推、包过、稳上岸、名额有限、有路子、有关系、百分之百、
  直接挑走、躺着吃香、一次搞定、包就业、保送、走捷径、稳了、必过。
- **含谐音 / 拼音 / 拆字 / 符号变体**，一律按原词处理，不做规避。
- 不夸大政策效果、不把「门槛写着大专及以上」写成「大专就能进」、不制造焦虑。
  > 项目既有事故：成片里剪掉过「百分之百安置」「直接挑走」这类承诺类表述。

### 2.2 不引导至风险不可控渠道

- 不留：手机号、微信号、二维码、外链、地址、邮箱。
- 不写：加我、私信我、进群聊、加群、转发给需要的人、集赞、扣 1、评论区留联系方式。
- 私域语境下**正常答疑语气**是允许的（「有拿不准的，先存下来对照原文看」「聊聊」），
  但不得变成明确的引流动作。

### 2.3 不编造事实

- 不编：数据、案例、政策名、单位名、客户评价、个人履历、具体经历、公告日期与名额。
- **无素材的纯文字需求尤其容易踩**：不写「今天去了某基地」「刚见了一位客户」「上周有三位战友…」。
- 配图不由文案反向补出画面里没有的内容。

### 2.4 不蹭热点

- 不蹭时政军事热点、不做局势解读、不评议、不借热点引流、不做未经核实的政策预测。

## 三、脱敏清单（截图与含人像素材必查）

```
□ 姓名 / 昵称 / 头像
□ 微信号 / 手机号 / 身份证号
□ 订单号 / 交易单号 / 银行卡 / 收款账号
□ 单位名 / 群名 / 部门名
□ 内部看板 / 表格 / 文件 / 通知原文
□ 可识别的设备铭牌、编号、工牌
□ 地理位置水印 / 拍摄时间水印
□ 聊天记录里第三人的发言内容
```

**规则**：以上一律**不进文案**；并在【需人工确认】提示「发布前请打码」。
聊天截图不得改写成「客户好评 / 成功案例」式结果背书（同时命中 2.1 与 2.3）。

## 四、金额素材的合规附加约束

无论定金位 / 全款位：

- 不写客户身份、不写「又成交一单」「收款 X 元」、不晒成果、不制造热闹。
- 不写「名额有限 / 涨价在即 / 最后几位」等逼单暗示。
- 不把款项与「包过 / 包分配 / 稳上岸 / 有结果」绑定。
- 不暗示后续必有尾款、不暗示名额或价格会变。
- 默认不写任何金额数字（`SHOW_AMOUNT=false`）；改 `exact` 须单次明确确认。

> **为什么默认不落「定金」二字**（`ALLOW_DEPOSIT_WORD=false`）：
> 「定金」在《民法典》中有定金罚则的特定法律含义。业务上存在分笔支付、单笔 <5 万实际属于全款一部分的情况，
> 若在朋友圈把这笔写成「定金」，容易被理解为交易性质失真。
> 因此默认用「意向金 / 预付款 / 先定下来 / 剩下的流程慢慢走」传达**同一种阶段性口吻**，不做法律定性。
> **参数打开后即可正常使用「定金」**——这是可配置项，不是禁令。

## 五、账号既有克制话术（可沿用）

| 场景 | 可用句 |
|---|---|
| 讲政策 / 招录条件 | 「只讲公开可查的信息，不承诺任何结果」 |
| 讲岗位门槛 | 「不是包分配、不是躺着吃香」 |
| 讲地区差异 | 「具体岗位和要求各地不一样，以官方公告为准」 |
| 视频成片免责（本项目统一） | 「无不良引导，不引导至风险不可控渠道」 |

> 朋友圈文案**默认不硬塞免责**。`DISCLAIMER=auto` 时，仅涉及政策解读 / 款项 / 招录条件的条目
> 在正文末尾自然带一句，不单独起行、不加「免责声明：」字样。

## 六、出稿前合规自检表（复制到脑内过一遍）

```
[ ] 有没有装备型号 / 参数 / 内部编号 / 未公开项目？
[ ] 有没有厂区位置、内部布局、在职人员姓名职务？
[ ] 有没有内部文件、通知、群聊原文、看板内容？
[ ] 有没有未公开招录计划、名额、非公开数据？
[ ] 画面里的敏感元素有没有被复述 / 放大 / 推断？
[ ] 专名有没有未经确认就落字？
[ ] 截图个人信息有没有全部挡在文案之外，并提示打码？
[ ] 有没有结果承诺或它的谐音 / 拼音 / 拆字变体？
[ ] 有没有联系方式 / 二维码 / 外链 / 加群 / 转发诱导？
[ ] 有没有编造数据、案例、政策名、单位名、客户评价、具体经历？
[ ] 有没有蹭时政军事热点 / 局势解读？
[ ] 金额素材：判定对不对？数字有没有漏写？有没有写「又成交一单」？
```

**命中处理**：改写或整条废弃，**不在输出里保留违规版本、不解释"本来想写什么"**。
【合规自检】里写「通过」或「命中并已改写（写明改法）」。
