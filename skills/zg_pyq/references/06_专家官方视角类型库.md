# 06 · 专家／官方视角类型库（能力知识库）

> **本文件只保存抽象结构、判定信号与写作规则**，不含任何素材原文、业务原句或真实专名。
> 它是「能力知识库」而不是对外介绍：例子不进文档，能力进规则。
> **规则以 `../专家提示词.md` 为准**；本文件负责把「专家／官方向」这一档讲透。

---

## 一、为什么需要这一档

默认档是**顾问视角**：第一人称「我」、活人感、口语、结尾留白，适合日常配图与轻互动。
但账号还有一类内容，目的不是陪着聊天，而是**立调性、建专业权威、做信息交付**：
第三人称或去人称、资讯密度高、有明确立场、结构感强，**不口语、不生活化、不煽情**。

因此新增 `VOICE` 视角档位与 6 类产出类型（P1–P6）。
**默认档不变**（仍是顾问），只有素材明显命中下列信号时才自动切换，并在【本次判定】写明路由依据；用户可显式覆盖。

---

## 二、视角档位 `VOICE`

| 档位 | 人称 | 语气 | 句式特征 | 明确禁止 |
|---|---|---|---|---|
| `顾问`（默认） | 第一人称「我」 | 口语、有具体细节、有温度 | 长短交错、结尾留白 | 网红腔、承诺、逼单 |
| `专家` | 第三人称 / 行业观察者 | 克制、有判断、有信息量 | 陈述句为主，事实→解读→判断；可设问 | 煽情、夸大、绝对化、口头禅 |
| `官方` | 去人称 / 机构发布 | 平稳、准确、公告体 | 条目化、信息前置、少修饰 | 感叹号连用、表情符号、钩子、催促语 |

- `TONE_LIVELY` **只在顾问档生效**；专家／官方档忽略该参数（避免把通告写成生活化口语）。
- 三档都受同一套硬红线与默认克制基线约束，没有例外档。
- 专家／官方档可以用书面词（「聚焦」「覆盖」「以…为准」「公开列明」），但不得堆形容词与口号。

## 三、六种产出类型

### P1 · 价值凝练型（身份／作风）

| 项 | 内容 |
|---|---|
| 判定信号 | 军旅意象图、作风／荣誉／群体照、纪念性配图、只要求「配一句有分量的话」 |
| 立场与目的 | 官方宣传视角；立调性、树形象、强化身份认同，**不卖货、不转化** |
| 结构骨架 | `<对仗短句 A>，<对仗短句 B>` / `<对仗短句 C>，<意象或初心点题>` / `<一句群体／身份说明>` |
| 写作要点 | 短句、对偶、意象具体；2–3 行收住；不用解释、不加行动指令 |
| 专属改写 | 不写具体单位、人数、成果；不接岗位条件与名额；不蹭敏感时政节点 |
| 默认规格 | 2–3 条 / 20–50 字 |

### P2 · 政策解读型

| 项 | 内容 |
|---|---|
| 判定信号 | 政策文件、官方公告截图、新闻标题、含「方案／落地／扶持／紧缺领域／重点方向」的需求 |
| 立场与目的 | 专家／行业观察者；借**公开可查**的政策建立专业权威，把行业方向映射到岗位类别 |
| 结构骨架 | `<公开政策或方案> 落地` / `<领域方向> <动作>` / `聚焦 <公开列明的重点领域>，<相关方向> 在列` / `<岗位类别> 属公开紧缺方向` / `<一句价值判断：产教融合／技能积累／产业需要>` / `<克制收尾：以官方公告原文为准>` |
| 写作要点 | 先事实后解读；政策名、领域、数字**必须来自公开可查信息**，拿不准写「需人工确认」；不自行推演政策效果 |
| 专属改写 | 不写「重磅」等情绪词；不把政策解读成招录承诺；不编领域数量与扶持力度 |
| 默认规格 | 2 条 / 80–160 字 |

### P3 · 岗位／事项通告型

| 项 | 内容 |
|---|---|
| 判定信号 | 岗位条件清单、招录／培训通知、课程安排、多图信息表、要求「整理成一条通知」 |
| 立场与目的 | 官方发布；信息交付与筛选，条目化、可读、可核对 |
| 结构骨架 | `<事项名称>` / `<主办或合作信息（仅公开可确认）>` / `<条件条目：年龄／学历／专业方向／工作时间／地点／周期>` / `<培养与去向：仅公开口径>` / `<注意事项：条件与名额以公告原文为准>` |
| 写作要点 | 纯文本分行、同类项对齐；只用用户给的且可公开的信息；缺项写「需人工确认」，不补 |
| 专属改写 | **不写**名额限量、先到先得、催促语、重复感叹号、表情符号；**不写**结果承诺与绝对化单位性质表述；**不写**未公开的内部流程、单位代号、合作方细节 |
| 默认规格 | 1 条 / 150–300 字（本档唯一允许的长文案） |

### P4 · 人物／工匠纪实型

| 项 | 内容 |
|---|---|
| 判定信号 | 人物照、荣誉或证书、技艺／成果材料、师承叙事、行业人物报道素材 |
| 立场与目的 | 专家／机构视角；以专业纵深与真实成就建立可信度 |
| 结构骨架 | `<一句成就或定位概括>` / `<技艺、方法或创新点（公开可查）>` / `<团队与带教／传承>` / `<行业价值或精神>` / `<头衔或荣誉（须人工确认，否则整项不写）>` |
| 写作要点 | 纪实质感、术语准确；不虚构经历与数据；师承关系只在用户给出时写 |
| 专属改写 | 人名、单位、荣誉、数量**未经确认不落字**；不把人物成就转成招录承诺；不写未公开项目与内部编号 |
| 默认规格 | 1–2 条 / 120–250 字 |

### P5 · 节点关联型

| 项 | 内容 |
|---|---|
| 判定信号 | 节气／行业公开主题日海报、当日活动现场图、集体活动照、纪念日配图 |
| 立场与目的 | 官方视角；借节点做主题连接与价值共鸣，把账号议题接入公共语境 |
| 结构骨架 | `<节点句>` / `<价值对仗句>` / `<现场事实（不带未核实数字）>` / `<群体品质与岗位要求的对应关系>` / `<双向价值判断>` / `<克制收尾>` |
| 写作要点 | 庄重、克制、不做情绪动员；节点与业务的连接要自然，不硬拗 |
| 专属改写 | **仅限**节气、行业公开主题日、账号自有活动节点；**敏感历史／时政／军事节点一律不做业务关联**（仅可庄重致意，且建议换素材）；不写未核实的到场人数、通过人数、成绩 |
| 默认规格 | 2 条 / 60–120 字 |

### P6 · 服务逻辑／方法论说明型

| 项 | 内容 |
|---|---|
| 判定信号 | 流程图、闭环示意图、答疑式需求、「凭什么／怎么做得到／逻辑是什么」类提问 |
| 立场与目的 | 专家／机构自述；回应质疑、解释机制、建立信任，不靠情绪推动 |
| 结构骨架 | `<设问>` / `<环节一：公开可说的机制>` / `<环节二：>` / `<环节三：>` / `<因果总结句>` / `<概念收束或定位句>` |
| 写作要点 | 每环节一句话，讲清「依据—动作—结果」；只描述可公开、可核实的环节 |
| 专属改写 | **不写**结果承诺与「保证／包／一定」类词；不写未公开的内部筛选、审核、政审等流程；不用表情符号和数字序号图标；不用「因为懂…所以能…」式绝对化自证 |
| 默认规格 | 1–2 条 / 100–200 字 |

## 四、路由流程（自动匹配，可覆盖）

```
输入素材 / 需求
  ↓ ① 用户是否显式写了 VOICE 或 OUTPUT_TYPE？ → 是 → 直接采用（覆盖优先）
  ↓ 否
  ↓ ② 识别判定信号（见上表）——按「最具体」的信号取一个主类型
  │    政策文件/公告  → P2      条件清单/通知 → P3
  │    人物/荣誉材料  → P4      节点海报     → P5
  │    流程图/答疑式  → P6      军旅意象/求金句 → P1
  │    都不命中       → 回落默认顾问档（不套 P 类型）
  ↓ ③ 定 VOICE：P1/P3/P5 → 官方；P2/P4/P6 → 专家（用户可覆盖）
  ↓ ④ 查决策表定条数与字数
  ↓ ⑤ 合规闸前置：把该类型专属改写项 + 硬红线 + 基线一起列出
  ↓ ⑥ 起草 → 编辑 → 自检 → 输出
```

【本次判定】必须新增两字段：`产出类型＝P?（依据：<命中信号>）`、`视角档位＝?`。
回落顾问档时写 `产出类型＝默认`、`视角档位＝顾问`。

## 五、这一档的合规闸（从真实业务文案中提炼的高风险项）

| 特征类别 | 处理 |
|---|---|
| 结果承诺类（包就业／包安置／保证上岗／定向去向／直签承诺） | 命中基线 → 改写为「按公开流程培养与考核，具体条件与去向以官方公告为准」；**不输出原表述** |
| 限量与催单类（名额数字、先到先得、数量有限、速看、催促语、重复感叹号） | 整句删除或改为中性信息句；名额统一写「以公告原文为准」 |
| 表情符号与图标序号（各类 emoji、数字序号图标、平台表情、话题标签） | 专家／官方档默认不用；结构化改用纯文本分行与短横线 |
| 网红腔与情绪词（重磅、炸了、家人们、谁懂、绝对化自证） | 沿用既有「活人感 ≠ 网红腔」禁令，同时适用于三档 |
| 专名与头衔（企业名、子公司名、人名、荣誉、单位代号） | 未经确认不落字，写「需人工确认」占位；不写「国控／国参」等未公开口径 |
| 数据与成果（到场人数、通过人数、通过率、架次、产值） | 未经证实不写；需要时标注需人工确认，不编造 |
| 内部流程（筛选、审核、背景核查、政审、内部编号） | 不复述、不推断，整项删除 |
| 敏感节点（历史／时政／军事纪念日） | P5 只做庄重致意或建议换素材，**不接业务、不接岗位信息** |
| 绝对化排他表述（只有某类单位、没有某类、唯一、百分百） | 改为「以公告列明的单位性质为准」等中性表述 |

> 这些是**改写规则**，不是可选风格。命中即改写或整条废弃，不在输出里保留违规版本。
> 硬红线（禁涉密与未公开信息）在任何档位都不可关闭；`BASELINE_STRICT` 的开关语义不变。

## 六、与既有规则的关系

- 输出**四小节固定结构不变**（候选块 / 【本次判定】/【合规自检】/【需人工确认】）。
- 正文规则：不带 markdown 修饰符号、不带 emoji、不带话题标签、不带引号与标题；
  **P3／P6 允许纯文本分行与条目化**（朋友圈常见排版），但不使用 `*` `#` `>` 等标记。
- 【合规自检】新增一句：`类型改写项：通过 / 命中并已改写（写明改法）`。
- 决策表 10 行 + 本档 6 行，共 16 行；单次【条数与字数】覆盖优先。
- 素材信息不足时，同样走「保守稿 + 需人工确认」，不为了套结构而编内容。

## 七、维护

新增一种类型 → ① 分配新 P 编号并写全六项（信号／立场目的／骨架／要点／改写／规格）
→ ② 在决策表加一行 → ③ 在路由流程加一条 → ④ 在自检清单加一项
→ ⑤ 用一个**中性自造**素材试跑，确认不会串回顾问档、不会漏改写项。
**任何情况下都不要把真实素材原文写进本文件或对外介绍文档。**
