### 由依据得到的三条事实

1. **折叠有两种，不是一回事**
   - **A · 单条内容折叠**：单条纯文字过长 → 收起为「全文」按钮。**官方未公布单条折叠的字数／行数阈值**；第三方数字互相矛盾，因此本技能**不写死任何字数阈值**。
   - **B · 多条动态折叠**：同一人短时间连发多条 → 只完整显示最新一条，其余收进「余下 x 条」。官方明确指向「批量或多次发送的营销类信息」「高频」「同质化」，且**判定在发布时刻完成、用户无开关**。
2. **折叠是平台对展示形式的动态处理**，与账号历史行为、发布节奏、内容相似度都有关。文案只能降低触发概率，**不能保证不被折叠**；技能**不承诺**「一定不折叠 / 100% 展开 / 亲测有效」。
3. **规避检测属于违规区**：零宽字符、隐形分隔符、特殊字符集、火星文、谐音替换、防折叠码、防折叠小程序、外挂群控、复制粘贴绕过检测——分别对应《规范》12.2 / 12.11 / 13.5 及外挂打击口径，也与本项目「不提供谐音／拼音／符号规避」的红线冲突。**一律不做，也不给操作指导。**

> 结论：本技能的「防折叠」= **提升内容质量与可读性、降低被判定为批量营销的概率**，
> 不是**绕开平台识别**。这是设计前提，不是可选项。

## 二、适合 / 不适合的自动判定（`ANTI_FOLD=auto`）

用户的核心要求：**适合提前优化的，输出时直接写成防折叠形态；实在不适合的，就不做。**

### 适合 → 默认直接做（无需用户额外要求）

| 命中条件 | 典型类型 |
|---|---|
| 报到 / 开班 / 实训 / 现场类（M1） | 决策表第 1–2 行 |
| 企业 / 签约 / 入职 / 去向类（M4） | 第 3 行 |
| 政策 / 新闻借势（M2） | 第 4 行 |
| 师资 / 荣誉 / 成果 | 第 6 行 |
| 节点借势（M6）、纯文字与认知观点（M5） | 第 7–8 行 |
| 学员反馈 / 聊天截图、金额截图（报名进度） | 第 9–10 行 |

共同特征：**中短文本、目的是让人一眼看到重点、压缩不会丢关键信息**。

### 不适合 → 明确不做（输出只写「未优化」四个字的结果）

| 命中条件 | 为什么不适合 |
|---|---|
| **M3 名额通告**（200–320 字条目化） | 条件、地点、周期、名额缺一不可；为防折叠压缩会丢条件、造成误导 |
| 政策原文需要逐条列明 | 引述须完整，压缩即失真 |
| 用户显式要求「完整清单 / 长文 / 原文照发」 | 用户意图优先 |
| 素材信息不足，压短必须靠推测补内容 | 会触发「不编造事实」底线，宁可保留保守稿 |
| 结构本身要求完整呈现（长通告、合同条款） | 改动会破坏语义 |

**不做的动作**：保持原稿完整，不为凑防折叠删信息；**判定里只写 `防折叠：未优化`，不写原因**；
**不擅自替用户改写主稿**。

## 三、具体做法（只做内容层 / 排版层）

按优先级，前两条是确定性收益，不依赖任何未公布的阈值。

1. **首句自足（最重要）**：第一句就自带最有价值的信息或结论——即使被折成一行，好友也能看到重点。
   禁止把关键信息压在末句，禁止用「今天翻到一张…」「最近有件事…」这类空开场占用首句。
   专家／官方档同理：结论、事项名、最关键的公开事实放最前。
2. **控制单条篇幅**：按决策表区间走，中短为主；明显超出时才拆。
   不把三条候选写成三段长文；不为「看起来丰满」加水句。
3. **自然分段、一段一意**：短句、段间留白，避免密不透风一大段；
   **不批量堆空行**（异常排版本身是低质信号）。M3 的纯文本条目化保持原样。
4. **原创化、去模板感**：同批候选**首行信息点各不相同**，不只是换词；
   不用统一模板套多条；emoji 控制在 2–6 个、不堆三连，三条候选不要都用同一句催促话术。
   这同时降低「由机器生成／批量同质营销」的特征。
5. **去掉官方明确反对的元素**：集赞、转发诱导、「提示分享朋友圈」、外链与二维码、引流第三方。
   联系方式按业务需要可留（业务方决定），但**集赞与转发诱导一律不做**。这一条既是合规，也是防折叠。
6. **多条发布节奏（内部判断，不输出）**：同批候选建议错峰发布、避免同一时段连发高度相似内容。
   这条只影响你给建议时的口径，**不写进输出**。

### 明确不做的动作（硬约束，不可被「防折叠」理由覆盖）

- 零宽字符 / 不可见字符 / 隐形分隔符 / 特殊字符集 / 防折叠码 / 火星文 / 谐音·拼音·拆字替换。
- 防折叠小程序、第三方「智能优化」工具、外挂、群控、批量粘贴工具。
- 「先打一个字再粘贴」「备忘录二次清格式」「首尾加小众符号」等**绕过输入来源识别**的操作指导。
- 为防折叠编造信息、删掉必要条件、改动已核实的公开事实。
- 承诺「保证不折叠 / 100% 展开 / 亲测有效」。

> 命中即视为不可输出项，**换写法，不输出该版本**；输出里不解释这条边界。

## 四、参数与输出字段

```
ANTI_FOLD = auto   # auto / on / off
```

| 值 | 行为 |
|---|---|
| `auto`（默认） | 按第二节自动判定；适合就做，不适合保持完整 |
| `on` | 对适合类型强制做；**对不适合类型仍不做**（不适合 ≠ 不想做） |
| `off` | 完全不做 |

单次覆盖（写在【需求】或【补充】里）：
`做防折叠` / `不用防折叠` / `这条要完整清单，不要压缩` / `首句给结论`。

**输出字段（只有一行结果，不写细节）**

```
【本次判定】
素材类型：视频
视角档位：招生方
防折叠：已优化
```

> 就这三行。**不写**"做了首句自足/篇幅/分段/去营销腔"，**不写**未优化的原因，**不写**发布节奏，
> **不写**防折叠边界结论。

## 五、判定流程（放在起草之前）

```
Step 2 之后 → 判定 ANTI_FOLD：
  用户显式覆盖？ → 按覆盖值
  否则命中「不适合」表？ → 不做，输出写「未优化」即止
  否则 → 做，起草时按第三节 1–5 条写进正文
Step 4 起草 → 首行自足优先于任何其他修辞
Step 5 自检 → 有没有符号规避 / 第三方工具 / 为压短丢条件？
Step 6 输出 → 判定里只写一行结果
```

## 六、维护提示

- 折叠规则由平台动态调整，**本文件记录的官方条款与日期需定期复核**；
  若官方公布新的明确阈值，只改「事实依据」与「篇幅控制」两处，不要改合规边界。
- **任何情况下都不要把第三方 SEO 站的经验数字写成硬规则**（历史上出现过 99/100/120/200 字互相矛盾）。
- 新增素材类型或产出类型时，回到第二节补一行「适合 / 不适合」判定，并在
  `05_示例库.md` 补一个完整示例。
